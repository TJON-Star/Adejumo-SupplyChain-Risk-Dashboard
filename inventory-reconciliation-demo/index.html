How to interpret the results

Variance quantity = Physical quantity − Book quantity.

A negative variance means the physical count is below the book balance. A positive variance means it is above the book balance. Both require source-document review and, where appropriate, recount and authorised adjustment.

The dataset contains 48 count lines, of which 47 are marked Counted and one is Pending. The 36 non-zero variances are calculated only from the 47 completed lines. There are 37 action records, all currently open or in progress in this demonstration.

Power BI implementation

  1. Download the companion Excel workbook from the conversation.
  2. In Power BI Desktop, choose Home → Get Data → Excel workbook.
  3. Import Items, Locations, Transactions, PhysicalCounts and ActionLog.
  4. Create one-to-many relationships from Items and Locations to each fact table.
  5. Use the DAX measures in PowerBI_Measures.dax to create the KPIs.
  6. Build an item variance bar chart, category variance chart, action-status visual and reconciliation detail table.

Important: this GitHub page is a lightweight portfolio preview, not a native Power BI report (.pbix). It does not connect to live inventory systems.

All source records, SKUs, quantities, locations, dates and unit costs are fictional. The workbook contains the full simulated transaction and count-level dataset. A variance is an exception for investigation; it is not proof of theft, fraud or loss. Any client deployment must use approved source records, documented count cut-off, retained count evidence, controlled adjustments and agreed valuation rules.
